# P5 前端配合清单（引擎底座夯实 + 四角色端升级）

> 后端已全部实现并通过编译验证。本文档面向前端，按角色列出需要新增/改造的页面、
> 接口出入参字段表与交互约定。**先部署后端（执行 P5 SQL → 打包新 jar），再联调前端。**

| 顺序 | 动作 | 说明 |
|---|---|---|
| 1 | 执行 `src/main/resources/db/补论文全生命周期P5.sql` | 幂等可重复；漏跑则新接口全站 500 |

## 1. 全局约定

### 1.1 查重指标口径升级（影响所有展示重复率的位置）

新查重任务起，`check_rate`（即论文上的 `similarity_rate`）语义升级为**总相似比**：

| 指标 | 含义 | 建议展示文案 |
|---|---|---|
| checkRate / totalSimilarityRate | 总相似比 = 非引用命中句字数 ÷ 正文字数 | 「总相似比」 |
| maxPerSource | 单篇最大相似比 = 单篇来源命中字数 ÷ 正文字数的最大值 | 「单篇最大」 |
| citationRate | 引用率 = 引注命中句字数 ÷ 正文字数（不计入总相似比） | 「引用率」 |

- 存量任务（P5 上线前）无 maxPerSource/citationRate，字段为 `null`：前端对 null 显示「—」，不显示 0
- 百分比统一保留 2 位小数，后端已按 `15.32` 形式返回（不带 % 号），前端拼接 `%`

### 1.2 新增业务错误码

| errorCode | HTTP | 含义 | 前端处理建议 |
|---|---|---|---|
| 40912 | 409 | 评阅分配被拒：该论文无「合格」查重签核记录 | message 展示给管理员，提示先联系导师完成签核 |
| 40913 | 409 | 重复签核：该论文最新任务已有签核记录 | message 展示，禁止再次提交 |
| 40914 | 409 | 成绩合成失败：缺指导分（导师未签核） | message 展示，引导「待导师补签后重算」 |
| 40915 | 409 | 成绩合成失败：权重合计 ≠ 100 | message 展示，引导超管修正权重配置 |
| 40916 | 409 | 查重额度不足：学院当月额度已用尽 | 学生端 message 展示「学院本月查重额度已用完」 |

### 1.3 新增通知类型（NoticeType 枚举，消息中心需能渲染）

| type | 标题 | 默认内容 |
|---|---|---|
| CHECK_SIGNOFF_REJECTED | 查重报告签核退回 | 您的论文查重报告未通过导师签核，请按导师意见修改后重新提交 |
| SCORE_SYNTHESIZED | 总评成绩已合成 | 您的论文总评成绩已合成完成，请登录系统查看详情 |

### 1.4 通用注意

- 雪花 ID（taskId/paperId/hitPaperId/collegeId/策略 id 等）一律按**字符串**接收与回传，防 JS 精度丢失
- 统一返回体：`{ code, errorCode, message, data }`，code=200 成功；40912~40916 时 code=409
- 新学位字典 `degree_type`：undergraduate（本科，默认）/ master（硕士）/ doctor（博士）

## 2. 学生端

### 2.1 检测结果页改造（存量页面，改指标展示）

查重任务列表/详情中原「重复率」标签改为「总相似比」，并补两个指标位：

- 有值（P5 新任务）：三指标并列展示
- maxPerSource / citationRate 为 null（存量任务）：显示「—」，布局不塌

任务详情接口（`GET /api/student/check-tasks/taskDetail?paperId=` 与 `GET /api/enhanced/check-tasks/{taskId}`）的 `CheckTaskResultDTO` 已补输出 `maxPerSource` / `citationRate`（Double，存量任务为 null）。

句级明细数据不在任务列表接口里，点击「查看检测明细」跳新页（2.2）。

### 2.2 新页：句级检测明细

```
GET /check/api/papers/check-tasks/{taskId}/sentence-detail
权限：论文属主本人 / ADMIN / SUPER_ADMIN；非属主返回 403
```

**响应 data（SentenceDetailResultVO）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| taskId | string | 查重任务ID |
| checkRate | number | 总相似比（%） |
| maxPerSource | number \| null | 单篇最大相似比（%） |
| citationRate | number \| null | 引用率（%） |
| hitCount | number | 命中句总数 |
| items | SentenceDetailItemVO[] | 句级明细，全量，按句序号升序 |
| sources | SentenceDetailVO[] | 来源聚合列表，按占比降序 |

**items 单条（SentenceDetailItemVO）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| sentenceIndex | number | 句序号（从 0 开始，剔除参考文献区块后） |
| sentenceText | string | 句子文本 |
| similarity | number | 句相似度（%） |
| isCitation | 0/1 | 是否引用句（1 = 引注命中，不计入总相似比） |
| startOffset | number | 句子在正文中的起始偏移（可用于正文定位标红） |
| hitPaperId | string | 命中来源论文ID |
| hitPaperTitle | string | 命中来源论文标题 |

**sources 单条（SentenceDetailVO）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| hitPaperId | string | 来源论文ID |
| hitPaperTitle | string | 来源论文标题 |
| sentenceCount | number | 命中句数 |
| citationSentenceCount | number | 其中引用句命中数 |
| avgSimilarity | number | 组内句相似度均值（%） |
| sharePercent | number | 该来源占全部命中字数的百分比（%） |

**页面布局建议：**

1. 顶部指标卡：总相似比（大字）+ 单篇最大 + 引用率 + 命中句数
2. 来源列表（sources）：表格或卡片，展示 sharePercent 进度条 + sentenceCount + avgSimilarity；点击某来源过滤下方句列表
3. 句级明细（items）：默认按句序号展示；引用句（isCitation=1）用灰色/蓝色标签「引用」，普通命中用红色系按 similarity 分档（≥80 深红 / 50-80 浅红）
4. 空态：`items` 为空时展示「该任务为历史数据，未生成句级明细，仅提供总相似比」（存量任务无此数据，属正常现象，**不要当报错处理**）

### 2.3 新页/新模块：重复率趋势

```
GET /check/api/papers/{paperId}/similarity-trend
权限：论文属主本人 / ADMIN / SUPER_ADMIN
```

**响应 data：`SimilarityTrendVO[]`**（按查重完成时间**升序**，只含有效查重）

| 字段 | 类型 | 说明 |
|---|---|---|
| taskId | string | 查重任务ID |
| checkTime | string | `yyyy-MM-dd HH:mm:ss` |
| repeatRate | number | 该次总相似比（%） |
| maxPerSource | number \| null | 单篇最大（存量点为 null） |

**布局建议：** 折线图（x=checkTime，y=repeatRate），maxPerSource/citationRate 可选叠加第二/三条线（有 null 的点断开）；空数组显示「暂无查重记录」。

## 3. 教师端

### 3.1 查重报告签核（核心新功能）

**入口：** 教师端论文列表/详情中，状态处于「查重完成」的论文提供「签核查重报告」按钮。

**查看报告后提交：**

```
POST /check/api/teacher/papers/{paperId}/check-signoff
权限：TEACHER（且必须是该论文 teacher_id 本人）
Content-Type: application/json
```

**请求体（PaperCheckSignoffReq）：**

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| qualified | number | 是 | 1 或 0 | 1=合格放行 / 0=不合格退回 |
| guidanceScore | number | 是 | 0~100 | 指导评分（**不合格也必填**：它是总评成绩合成的指导分数据源） |
| comment | string | 否 | ≤500 字符 | 签核意见 |

> paperId 走路径参数，请求体不需要传；重复签核返回 40913。

**交互建议：**

- 弹窗内：签核结论单选（合格放行/不合格退回）+ 指导评分数字输入 + 意见文本域
- 提交成功后刷新列表；退回时学生收到 CHECK_SIGNOFF_REJECTED 通知

### 3.2 新页/模块：指导进度看板

```
GET /check/api/teacher/dashboard/guidance-progress
权限：TEACHER
```

**响应 data（GuidanceProgressVO）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| total | number | 我指导的论文总数 |
| statusSummary | {paperStatus, count}[] | 论文状态分布（状态码为 paper_status 字典值，历史脏数据原样透出，前端用字典翻译，未知值显示原文） |
| papers | PaperItem[] | 最近 50 条明细（create_time 降序） |

**PaperItem：**

| 字段 | 类型 | 说明 |
|---|---|---|
| paperId | string | 论文ID |
| paperTitle | string | 论文标题 |
| studentName | string | 学生姓名（空回落 username） |
| paperStatus | string | 论文状态码 |
| similarityRate | number \| null | 最近一次总相似比（null=未查重） |
| finalScore | number \| null | 总评成绩（null=未合成） |

**布局建议：** 顶部 total + 状态分布（饼图/标签组），下方论文表格（每行提供「去签核」入口，与 3.1 打通）。

## 4. 管理端（ADMIN）

### 4.1 新页：全校统计报表

三个查询接口 + 一个导出，均为 GET，权限 ADMIN：

```
GET /check/api/admin/stat-report/similarity-distribution
GET /check/api/admin/stat-report/college-compare
GET /check/api/admin/stat-report/monthly-trend
GET /check/api/admin/stat-report/export        ← 浏览器直接下载 xlsx（无需 token 以外的参数）
```

**similarity-distribution → `SimilarityDistributionVO[]`（固定 10 桶，有序，缺失桶已补 0）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| bucket | string | "0-10"、"10-20" … "90-100"（左闭右开，末桶含 100） |
| count | number | 该区间查重结果数 |

→ 柱状图直接渲染，x 轴用 bucket 原文。

**college-compare → `CollegeCompareVO[]`：**

| 字段 | 类型 | 说明 |
|---|---|---|
| collegeId | string \| null | 学院ID（null 行 collegeName=「未分配」） |
| collegeName | string | 学院名称 |
| avgRate | number | 平均相似度（%） |
| total | number | 论文数 |

→ 横向条形图或表格，按 avgRate 降序建议。

**monthly-trend → `MonthlyTrendVO[]`（最近 12 个月，升序）：**

| 字段 | 类型 | 说明 |

**export：** `<a href>` 或 window.open 触发下载（携带登录态 cookie/token 按项目现有下载方式），xlsx 含「查重结果分布/学院对比/月度趋势」三个 sheet，前端无需解析。

### 4.2 新页/模块：学院月度查重额度配置

挂在既有「查重规则/系统配置」页（AdminRuleConfig 同域）：

```
GET /check/api/admin/config/check-quota/list?quotaMonth=&currentPage=1&pageSize=10
POST /check/api/admin/config/check-quota/save
权限：ADMIN
```

**list 响应：** MyBatis-Plus `Page<CheckCollegeQuotaVO>`（`records/total/size/current` 结构）

**CheckCollegeQuotaVO：**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 记录ID |
| collegeId | string | 学院ID |
| collegeName | string | 学院名称 |
| quotaMonth | string | "yyyy-MM" |
| totalQuota | number | 当月总额度（次） |
| usedQuota | number | 当月已用（次） |

**save 请求体（CheckQuotaSaveReq）：**

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| collegeId | string | 是 | 学院ID |
| totalQuota | number | 是 | ≥0 |
| quotaMonth | string | 否 | "yyyy-MM"，缺省当前月 |

**交互建议：** 月份选择器（默认当前月）+ 学院下拉 + 额度输入；列表展示 usedQuota/totalQuota 进度条；保存即 upsert（同学院同月份覆盖）。**注意 list 接口必须显式传 currentPage/pageSize**（项目既往踩坑：缺分页参数直接报错）。

### 4.3 评阅分配改造（存量流程加拦截提示）

`POST /api/admin/review-assign/allocate` 流程不变；当目标论文无合格签核时返回 40912。分配按钮的失败提示按 1.2 表格处理即可，**无新接口**。

### 4.4 新动作：总评成绩重算（兜底入口）

**入口建议：** 论文管理列表行内按钮「重算总评」，对 final_score 为空或需要修正的论文使用。

```
POST /check/api/admin/thesis/{paperId}/recompute-score
权限：ADMIN
```

**响应 data：** 新的总评成绩（number）。

**错误处理：** 40914（缺指导分）→ 提示「导师未完成签核，暂无指导分」；40915（权重非法）→ 提示联系超管修正权重。成功后刷新列表回显 finalScore。

## 5. 超管端（SUPER_ADMIN）

### 5.1 新页：学位检测策略集

```
GET    /check/api/super/check-policy/list
POST   /check/api/super/check-policy/save
DELETE /check/api/super/check-policy/{id}
权限：仅 SUPER_ADMIN（ADMIN 调用返回 403）
```

**list 响应：`CheckPolicyVO[]`**（按 degreeType 升序）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 策略ID |
| degreeType | string | undergraduate / master / doctor |
| threshold | number | 合格阈值（%，0-100） |
| maxPerSource | number | 单篇最大上限（%，0-100，必填） |
| maxCheckCount | number \| null | 最多查重次数（null=沿用全局配置） |
| checkInterval | number \| null | 查重间隔秒（null=沿用全局配置） |
| enabled | 0/1 | 是否启用 |
| createTime / updateTime | string | `yyyy-MM-dd HH:mm:ss` |

**save 请求体（CheckPolicySaveReq）：** 字段同上（无 id），按 degreeType upsert——同一个学位类型再次保存即覆盖。

**布局建议：** 三行固定表（本科/硕士/博士），行内编辑 + 启停开关 + 删除；表单校验：threshold 与 maxPerSource 必填 0-100，maxCheckCount 正整数或留空，checkInterval ≥0。

**机制说明（可放进页面提示文案）：** 命中 enabled=1 的策略取其 threshold 作为合格线；删除/停用后该学位论文回落到既有阈值链路（学科>学院>全局），删除是安全的。

## 6. 公开验真页（无需登录）

面向任何访客（用人单位/期刊等），**请求不携带 Authorization 头**：

```
GET /check/api/report/verify/{reportNo}
限流：同 IP 60 次/小时；超出返回 code=500 + message「验真请求过于频繁，请 1 小时后再试」
```

**响应 data（ReportVerifyVO）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| reportNo | string | 报告编号 |
| valid | boolean | true=编号存在且哈希比对一致 |
| paperTitle | string | 论文标题（打码：首尾各 2 字符 + ****） |
| checkRate | number | 总相似比（%） |
| maxPerSource | number \| null | 单篇最大（%） |
| citationRate | number \| null | 引用率（%） |
| checkTime | string | 查重完成时间 |
| message | string | valid=false 时的原因（如「历史报告未生成验真数据」「内容哈希不一致」） |

**页面建议：** 独立公开路由（不进登录守卫），报告编号输入框 + 验真按钮；结果卡三态——
- 绿色「验真通过」+ 指标与时间
- 红色「验真不通过」+ message
- 黄色「无法验真」（valid=false 且 message 含「历史报告」）

## 7. 联调注意事项

1. **存量数据兼容**：所有新指标字段可能为 null（存量任务），一律「—」展示，勿按 0 处理；句级明细接口对存量任务返回空 items（正常空态，不是错误）
2. **分页参数必传**：额度 list 接口显式传 `currentPage/pageSize`
3. **雪花 ID 字符串化**：所有 19 位 ID 按字符串处理
4. **总相似比 ≠ 旧重复率**：同一篇论文 P5 前后两次查重数值会有差异（口径变化），趋势页两条口径混排属预期，无需做换算
5. **degree_type 预留**：论文提交表单本轮**无需**新增学位类型输入（后端暂未接收该字段，存量默认本科）；后续接入时前端再加下拉（字典 degree_type）
6. **外部引擎不可选**：引擎类型下拉如有 third_party/deep_learning 选项，本轮置灰并提示「API 对接待产品确认」，不要允许选中提交
